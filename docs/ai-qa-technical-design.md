- 日期：2026-11-20（2026-11-23 核对当前实现）

## 1. 架构与选型

当前后端为模块化单体。空间、发布和审计共用 PostgreSQL，文档解析、索引重建、发布与回答由定时 Worker 从数据库队列领取。同一产物可按 `PROCESS_ROLE` 选择运行 API、Worker 或两者。各类任务的容量和并发参数见后端详细设计。

| 层 | 当前职责与选型 |
| --- | --- |
| 前端 | Vue 3 + TypeScript（Vite 7）。工作台、知识库、助手与模板、发布管理、统计和系统设置各自成页；前端隐藏无权限入口，后端仍对每次访问鉴权。图表统一使用 echarts 并经 `BaseChart` 组件封装（按需注册、自适应、卸载销毁），页面只传配置对象。 |
| 业务服务 | Spring Boot，按知识库、发布与权限、问答、统计分模块；交付使用本地账号密码登录，部署细节见后端设计 §5。 |
| 元数据和任务 | PostgreSQL 存业务数据、待处理任务、发布状态、审计和统计事件。首期可用数据库任务队列，不预先引入消息中间件。 |
| 文件与检索 | 私有对象存储保管文档原件；检索先做文档名搜索与中文分词后的正文倒排。用政策样本评估后，再决定是否增加语义召回，不默认依赖向量数据库。 |
| 模型 | 问答通过后端模型适配器调用网关。单次提问可指定可用模型，省略时按全局默认配置解析。助手模板优先，缺省回退到全局模板。接入外部服务前需确认政策片段和会话数据的出域范围。 |

## 2. 核心数据契约

以下为逻辑数据对象，不是已存在的表名或 API 契约。

| 对象 | 记录内容与不变量 |
| --- | --- |
| 知识空间与授权 | 空间标识、用户访问授权、助手绑定权限、当前发布快照、发布代次。已授权不等于已发布。 |
| 文档版本和处理任务 | 空间、规范化文件名、不可变文档版本、原件位置、处理状态、索引结果。首期建议同一空间内按规范化文件名唯一；改名后的新版与旧版分别入库。 |
| 审核快照 | 冻结的文档版本清单及其政策有效性、替代关系等会影响问答的信息，关联审核人、审核结果及时间。不能修改待审快照，变更后生成新快照再提交。 |
| 会话、回答段落与证据依赖 | 段落记录空间、发布代次、文档版本及实际输入的证据；展示引用是该依赖的子集。输出按段落过滤，不依赖前端隐藏，也不靠事后从回答文字猜测来源。 |
| 使用事件与审计 | 会话标识、逻辑请求标识、模型调用标识、用户、结果、实际 Tokens、时间；审核、发布和撤回另记操作者、对象版本、结果和时间。 |

## 3. 关键流程

### 3.1 导入与检索（R01、R02）

1. 上传前检查空间维护权限、格式与大小；数据库唯一约束防止并发同名覆盖。批量导入逐文件登记状态，不因一个文件失败回滚整批。
2. 文档处理进程异步提取已有文字、分段并构建索引。纯扫描件进入「无可提取正文」，不做 OCR。处理结果和错误原因回写；暂时失败可按文档版本重试，任务幂等，不能产生重复索引。
3. 已完成处理但未进入当前已审核快照的文档，只在有维护权限的后台显示，不加入使用者的搜索和问答范围。请求在检索时就带上授权范围，返回结果前再次按当前发布状态校验；索引不能充当权限事实来源。

### 3.2 审核、发布切换与回退（R04）

草稿提交后生成冻结快照。系统管理员审核该具体快照；驳回记录原因，由提交用户修改后重提。建议已发布空间在重审期间继续使用原已审快照。审核通过且预期索引就绪后，在事务中切换当前发布指针并写入审计；切换失败时保留原已审版本，任务可重试。提交版本、审核版本、发布版本必须分别可追溯，旧审核任务不得覆盖较新的审核结果或重新激活已经撤回的空间。

### 3.3 问答与政策规则（R03）

模型可用的空间范围是 **助手可用绑定 ∩ 当前用户授权 ∩ 当前已发布空间**。检索保留文档版本和政策状态。明确失效的文件可作为历史信息，不作为现行依据；无法核实有效性时说明不确定。冲突回答按差异点组织，每个冲突点都关联相应文档。没有合格证据时返回明确提示，不生成无依据的确定结论。

当前实现对授权发布快照中的文本块做关键词排序，最多取 20 块。本次模型调用输入当前问题、有效模板及该批证据，将输出保存为一个回答段落并记录全部输入证据。展示引用由模型返回的证据序号映射到本次集合。新引用可预览所存文本块、文档版本、有效性及可用的来源位置，旧数据无片段时回退到文档预览。多轮历史与证据继承仍是后续扩展的约束。

### 3.4 撤回与历史屏蔽（R04）

- 撤回事务关闭空间的发布资格、更新发布代次并写审计。撤回以主库中的已提交状态为准，索引清理和缓存失效可异步完成；历史引用不会因重新发布自动恢复。
- 搜索、问答、文档预览/下载、会话历史及继续追问统一走服务端访问校验。普通用户的文档入口不向客户端交付可绕过撤回校验的对象存储地址。
- 历史读取时过滤撤回引用。某段依赖任一失去授权的来源即屏蔽整段，未受影响的段落照常显示。当前追问用新问题重新检索，模型调用只接收本次证据。
- 增量流只用于「让用户看到正在生成」：`GET /questions/{questionId}/stream` 以 SSE 下发模型增量，段落、引用与证据有效性仍以整段生成、校验并落库后的详情接口为准。检测到生成期间来源已撤回或权限已变化，照旧丢弃受影响结果并让客户端回退轮询读取终态，不把流式预览当作最终回答。撤回不能收回此前已经交付、被复制或下载到用户设备的数据。

### 3.5 统计与可追溯性（R05）

会话、逻辑提问、最终失败与实际模型用量分开记录，全部归属发起用户。用唯一标识防止网络重送或后台重复消费导致重复入账；模型多次真实调用如分别上报用量，按实际用量累计，不按空间重复计入。未上报 Tokens 单列，不用零填补。时间存 UTC，对外以 `Asia/Shanghai` 切分自然日、周、月。文档类统计按空间，已接收、可预览与正文可检索为不同口径，不混为同一指标。

## 4. 实施与验证

| 顺序 | 模块与产物 | 验证与通过标准 |
| --- | --- | --- |
| 1 | 空间权限、文件接入、解析任务、名称与正文搜索 | 并发同名上传不覆盖；新版改名后与旧版可查；纯扫描件不进入正文索引；重试不产生重复数据（AC01、AC02）。 |
| 2 | 冻结快照、审核状态流转、发布切换及审计 | 驳回可重提；未审变更不可见；索引或事务失败时原发布继续可用；旧审核请求不会覆盖新状态（AC05）。 |
| 3 | 多空间助手、证据依赖、撤回与历史过滤 | 验证授权交集、无依据、失效及政策冲突；模拟生成期间撤回，并检查旧链接、旧历史和继续追问（AC03、AC04、AC06）。 |
| 4 | 用户统计及监控 | 用跨空间、重试、失败、用量缺失和北京时间跨周期的固定记录对账；查询可解释且审计可追溯（AC07）。 |

发布快照切换和回答证据过滤已有实现及集成测试。真实政策样本的检索质量、复杂政策冲突和时延目标仍待业务验收，运行验证范围见[实施状态](./ai-qa-status.md)。
