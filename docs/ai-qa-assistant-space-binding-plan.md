# AI 问答｜助手与知识空间绑定重构方案

- 制定日期：2026-11-24
- 状态：P0 与 P1 均已实施（2026-11-24）
- 适用范围：`/assistant`（AI 助手）、`/assistant-config`（助手配置）两个页面，以及这两个页面依赖的助手/空间接口

## 1. 结论

业务主线应固定为 **助手 → 空间 → 问答**：管理员在助手配置里给助手绑定空间，用户问答时只选助手，检索范围由助手决定。

当前实现有四处偏离，其中两处直接导致「100 个空间找不到」：

| # | 现象 | 现状代码 | 性质 |
| --- | --- | --- | --- |
| P1 | 问答页让用户每次提问自己勾空间 | `AssistantView.vue` 提问区 `SpaceScopePicker`，默认全选并写 localStorage | 语义错位：把「助手的属性」暴露成「每次提问的选项」 |
| P2 | 问答页不能切换助手，只显示名字 | `activeAssistant` 仅来自 `route.query.assistant` 或 `assistants[0]` | 「问答关联助手」在界面上无法成立 |
| P3 | 助手配置绑定空间是 100 行开关平铺，无搜索、无已选区、无分页 | `AssistantConfigView.vue` 的 `bind-row` 循环 `spaces` | 直接对应「找不到、无法搜索、展示不过来」 |
| P4 | 助手列表「绑定空间」列只有「N 个空间」 | `AssistantConfigView.vue` `assistant.bindings.length` | 无法辨识绑的是哪些空间 |

另有一处隐藏缺陷：允许创建绑定 0 个空间的助手，而 `GET /assistants`（非管理视角）会把这些助手过滤掉，管理员建完在用户侧「找不到」，来源是数据而非 UI。

## 2. 现状事实（已核对代码）

**后端已具备的能力，不需要重做：**

- `GET /assistants` 已支持 `limit`/`offset` 并返回筛选后的 `total`（`QaController.listAssistants`）。
- 普通用户拿到的 `bindings` 已按「当前用户可读」过滤（`visibleBindings`），空绑定助手被剔除。
- `PUT /assistants/{id}` 全量替换绑定，`POST /assistants` 同样接受 `bindings`；管理员可绑定任意空间（`findForUser` 对系统管理员按全量权限计算）。
- `GET /spaces` 已支持 `q`（名称包含）、`status`、`limit`/`offset`，`limit` 省略时返回全部（`PageQuery`），上限 200。
- `POST /questions` 与 `POST /conversations/{id}/questions` 的 `requestedSpaceIds` 是可选的：不传 = 用助手全部绑定；传空数组 = 400。

**后端现状的边界：**

- 助手 `bindings` 只回传 `spaceId`，没有空间名或状态。前端要在列表里显示空间名，只能本地维护 id→name 映射。
- `GET /assistants` 没有名称筛选参数，助手多了列表无法搜索。
- `listSpaces()` 前端不传 `limit`，靠「省略即全部」拿到全量空间；超过 200 个空间后映射会缺项。

## 3. 目标模型

```
助手（assistant）
  ├─ 名称 / 回答模板 / 启停
  └─ 绑定空间 N 个（管理员配置）
          │
          ▼
用户提问：选助手 → 检索范围 = 助手绑定 ∩ 用户可读 ∩ 已发布
          │
          ▼
可选收窄（在助手绑定范围内勾选子集，默认全选）
          │
          ▼
回答与引用
```

三条规则：

1. **空间范围的上限由助手决定**，用户只能在助手已绑定的范围内收窄，不能扩大。
2. **助手绑定多个空间不扩大用户权限**（PRD 既有规则，保持不变）。
3. **助手至少要绑定 1 个空间**，否则普通用户看不到它；这条从「隐式过滤」变成「显式校验」。

## 4. 方案 A：问答页以助手为中心

### 4.1 交互

```
┌ 助手 [差旅政策助手 ▾]                       检索范围 [已选 3/3 ▾]
│
│  ……对话……
│
│  [模型 ▾]                                    [输入框] [发送]
└
```

- **新增助手切换器**（`chat-meta` 左侧）：下拉列出当前用户可见的助手（后端默认列表已过滤「启用中 + 至少一个可读绑定」），每项显示名称与空间数。
- **提问区的 `SpaceScopePicker` 保留为「范围内多选」**：可选集合是「助手绑定 ∩ 用户可读 ∩ 已发布」，默认全选，取消部分空间即收窄；弹层同时展示空间名、发布状态与可检索文档数，管理员额外显示「去助手配置」链接。
- **切换助手的行为**：
  - 当前无会话（草稿态）：直接切换。
  - 当前会话已有消息：轻确认「切换助手会开始新会话」，确认后把 `selectedAssistantId` 设为新助手并进入新会话草稿；取消则不变。
  - 会话一旦建立，归属助手不可变（后端 `conversation.assistantId` 已固定），切换只影响新会话。
- **请求变化**：全选时 `requestedSpaceIds` 传 `undefined`（等同不额外收窄，服务端按助手当前绑定取证）；只有用户取消部分空间时才提交选中子集。
- **范围不跨会话记忆**：当前实现按「可用空间集合」在内存中保留仍有效的选中项，换助手或空间撤回时自动回到全选；不再写入 localStorage，旧前缀 `aiqa.assistant.scope.*` 在进入页面时清理。
- **无可用空间**：发送按钮禁用，提示「该助手暂无可检索空间」；有可选空间但一个都没勾选时提示「至少选择一个空间」，两种情况都挡住提问，避免发出空范围。

### 4.2 状态归属

| 状态 | 归属 | 说明 |
| --- | --- | --- |
| `selectedAssistantId` | 组件 ref | 用户主动选择，优先于 `route.query.assistant` 与首项 |
| `activeAssistant` | computed | 当前会话的 `assistantId` → `selectedAssistantId` → `route.query.assistant` → `assistants[0]` |
| `availableSpaces` | computed | `助手 bindings ∩ canRead ∩ currentPublicationId`，即可选集合 |
| `selectedSpaceIds` | 组件 ref | 本次提问实际使用的空间；默认全选，换助手或空间撤回时自动回到全选 |

## 5. 方案 B：助手配置页绑定空间重构

### 5.1 交互

```
绑定空间（已选 3 / 可绑定 100）
┌──────────────────────────────────────────────────┐
│ 差旅政策 ×   年假制度 ×   考勤规则 ×   +9 展开     │  ← 已选区，chips
└──────────────────────────────────────────────────┘
┌ 搜索空间名称…                         [全选筛选结果] ┐
│ ☑ 差旅政策    已发布 · 12 可检索                     │
│ ☐ 年假制度    未发布 · 3 可检索                       │
│ ☐ 考勤规则    已发布 · 40 可检索                      │
│ …（服务端 q + 20/页，滚动加载更多）                   │
└──────────────────────────────────────────────────┘
```

- **两段式结构**：已选区与搜索结果分离。已选区不受搜索影响，解决「绑了 20 个、翻两屏就找不到」。
- **已选区**：
  - chips 显示空间名，`title` 显示状态与可检索数；单个 × 移除。
  - 超过 8 个折叠为「+N 展开 / 收起」。
  - 头部计数「已选 3 / 可绑定 100」。
- **搜索区**：
  - 输入框 300ms 防抖，调用 `listSpaces({ q, limit: 20, offset })`，`AbortController` 取消过期请求（复用 `api/http.ts` 既有能力）。
  - 结果项显示名称、状态徽标、可检索数；已在已选区的项显示「已添加」并禁用，不重复添加。
  - 底部「加载更多」或滚动加载；搜索无结果显示「没有匹配的空间」。
  - 「全选筛选结果」：添加当前筛选结果的全部（最多 200），二次确认，防止一次误绑几十个。
- **未发布空间的提示**：绑定允许，但在结果项与 chip 上标注「未发布（发布后才参与回答）」，不阻止绑定——管理员常需要先建助手后发版。
- **保存校验**：`boundSpaceIds.length === 0` 时拦截，提示「至少绑定 1 个空间，未绑定空间的助手不会出现在用户的助手列表里」。
- **助手列表列改造**：「绑定空间」列显示前 2 个空间名 + `+N`，`title` 列出全量（最多 10 个 + 省略）；映射缺失时回退「N 个空间」。
- **空间名映射**：弹窗打开时 `listSpaces({ limit: 200 })` 建 id→name 映射（当前规模 100 个足够）。超过 200 个空间时由 P1 的 `bindings[].spaceName` 补足。
- **布局**：保持弹窗上下堆叠，绑定区内部固定高度滚动（已选区与搜索列表各自区域）。不改成原型里的左右 grid——100 个空间的场景需要整宽给绑定区，左右分栏会把搜索列表压到 300px 级。

### 5.2 组件拆分

| 文件 | 动作 |
| --- | --- |
| `frontend/src/components/SpaceBindingPicker.vue` | 新增：已选区 + 搜索 + 分页，`v-model` 为 `string[]`，对外只暴露空间 id 数组 |
| `frontend/src/components/SpaceScopePicker.vue` | 改造：范围内多选，新增只读状态与「去助手配置」链接 |
| `frontend/src/views/AssistantConfigView.vue` | 重写绑定区与列表列；移除 `load()` 里对绑定渲染的全量依赖 |
| `frontend/src/views/AssistantView.vue` | 加助手切换器、移除 `SpaceScopePicker`、改请求参数、删除 scope localStorage |


## 6. 接口改动

| 接口 | 改动 | 阶段 | 兼容性 |
| --- | --- | --- | --- |
| `GET /spaces` | 无 | — | 已有 `q`/`status`/`limit`/`offset` |
| `POST /questions` | 前端不再传 `requestedSpaceIds` | P0 | 后端已支持省略，0 改动 |
| `PUT/POST /assistants` | 无 | — | `bindings` 仍只传 `spaceId` |
| `GET /assistants` | 新增可选 `q`（名称包含筛选） | P1 | 新增可选参数 |
| `GET /assistants` | `bindings[]` 增加 `spaceName`、`currentPublicationId` | P1 | 新增字段，向后兼容 |

P0 阶段后端零改动。P1 只在空间超过 200 个、或助手数量大到列表需要搜索时才必要。

## 7. 边界与状态

| 场景 | 预期行为 |
| --- | --- |
| 助手绑定 0 个空间 | 保存被拦截；已有历史数据不受影响，列表标记「无可用空间」 |
| 助手绑定的空间全部未发布 | 用户侧该助手不可见（后端已过滤）；管理员侧列表可见并标注 |
| 提问过程中空间被撤回 | `availableSpaces` 自动剔除，范围摘要随之更新；已问答的历史引用按既有规则屏蔽 |
| 空间数 > 200 | P0 映射不全时，列表列回退数量显示；P1 用 `spaceName` 解决 |
| 切换助手时有未发送的输入 | 保留输入内容，不随切换清空 |
| 多标签页同时编辑同一助手 | 沿用既有 `If-Match`/`ETag` 冲突提示，不改 |
| 搜索请求返回慢于后续输入 | `AbortController` 取消，不让旧结果覆盖新结果 |

## 8. 验收标准

造数据：100 个空间（其中 60 个已发布）、1 个助手、管理员账号。

| # | 场景 | 通过标准 |
| --- | --- | --- |
| AC1 | 打开助手编辑，搜「年假」 | 1 次输入即列出匹配项，不需滚动整个列表 |
| AC2 | 绑定 12 个空间，重新打开编辑 | 已选区一屏可见（或折叠展开），可逐个 × 移除，位置不随搜索变化 |
| AC3 | 已绑 12 个再搜一个已绑空间 | 该结果显示「已添加」且不可重复添加 |
| AC4 | 助手绑 30 个空间 | 列表「绑定空间」列显示前 2 个名 + `+28`，表格不撑破、不换行 |
| AC5 | 保存 0 个绑定 | 被拦截并提示，接口不发出 |
| AC6 | 问答页 | 提问区显示助手切换器与范围内多选控件，默认全选；取消部分空间后可正常提问 |
| AC7 | 切助手（无会话） | 直接切换，范围摘要更新 |
| AC8 | 切助手（有消息的会话） | 弹确认，确认后进入新会话草稿，旧会话保持原助手 |
| AC9 | 提问 | 全选时 `POST /questions` 请求体不含 `requestedSpaceIds`；收窄后只提交选中子集，且不会超出助手绑定 |
| AC10 | 助手无可用空间 | 发送禁用 + 明确提示 |
| AC11 | 搜「不存在」的空间名 | 显示「没有匹配的空间」，不报错 |

验证方式：`npm run lint`、`npm run typecheck`、浏览器实测（造 100 个空间后走 AC1–AC11），接口侧用后端日志确认 `requestedSpaceIds` 已省略。

## 10. 风险与回退

| 风险 | 应对 |
| --- | --- |
| 用户在范围内误收窄导致检索不到 | 默认全选；取消到 0 个时禁用发送并提示；切换助手或空间撤回后自动回到全选 |
| 切换助手弹确认打断流程 | 仅在会话已有消息时确认；草稿态直接切 |
| 搜索请求频繁 | 300ms 防抖 + `AbortController`；结果按 id 去重 |
| 已选区与搜索结果状态不同步 | 单一数据源：`modelValue: string[]`，搜索结果只做展示与「添加」，不持有选择状态 |
| 0 绑定拦截影响历史数据 | 只校验保存动作，不迁移存量；存量 0 绑定助手在列表标注 |
| 回退 | 保留 `SpaceScopePicker.vue` 文件；`AssistantView` 用常量 `SHOW_SCOPE_PICKER` 控制是否渲染，可一键回到旧交互 |

## 11. 已确认决策（2026-11-24）

1. **收窄保留在助手绑定范围之内**：提问区显示可多选的范围控件，默认全选；用户取消部分空间即收窄本次取证范围，但不能超出助手绑定。全选时不传 `requestedSpaceIds`。（2026-11-24 修订：此前一度改为只读摘要、完全不收窄，现按实际实现恢复为「可在绑定范围内收窄」。）
2. **问答页允许切换助手**：有消息的会话切换时确认并新建会话，旧会话保持原助手。
3. **助手必须至少绑定 1 个空间**：保存时拦截；存量 0 绑定数据不迁移，列表标注「无可用空间」。
