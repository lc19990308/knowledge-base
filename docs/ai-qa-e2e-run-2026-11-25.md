## 路由与主链路

实测路由：`/`、`/login`、`/403`、`/knowledge`、`/import`、`/documents/:id`、`/publishing`、`/assistant`、`/assistant-config`、`/answer-templates`、`/settings`、`/statistics` 与不存在的路由。浏览器 API 监听未发现未处理页面异常。

- **登录与权限**：四类本地账号通过真实登录表单及 Cookie 登录；错误密码被拒绝，三种管理员路由正确进入 403，退出后旧会话返回 401。
- **知识库导入**：三个入口共用导入模态。五种正文格式进入 `READY`，扫描 PDF 为 `NO_TEXT / NO_EXTRACTABLE_TEXT`，误标 PDF 为 `REJECTED / SUSPICIOUS_FILE`。同名文件重复上传跳过且不修改原草稿。维护者在授权范围内操作，读者不能导入。现行空间预览与草稿读回均成功，驳回后维护者可查看拒绝原因并重提。
- **文件边界**：10 MiB 文件成功写入、解析并进入草稿；Chromium 捕获到 XHR 字节事件及实际渲染进度 `0% → 100%`。10 MiB + 1 字节文件先由浏览器拦截，再以相同角色通过 API 验证 HTTP 413 与 `PAYLOAD_TOO_LARGE`。为了让超限请求穿过 Spring multipart 解析层进入业务逻辑，隔离启动的后端临时将容器 multipart 单文件上限提高至 11 MB；`ImportService` 仍按配置的 10 MiB 上限拒绝，项目默认环境与应用代码未被改动。
- **发布**：真实执行提交、管理员驳回、维护者查看拒绝原因后重提、快照复核、审核生效与撤回。过时草稿版本提审返回 412、`ETAG_MISMATCH`，前端重读 ETag，线上发布仍未变化。
- **问答和会话**：首问自动建会话，后续问题复用 ID；切换助手需要确认，不创建空会话；归档、恢复、取消删除、确认删除都有服务端读回。
- **引用和撤权**：引用弹窗核对来源位置、版本和证据短句。下载原件 SHA-256 与导入原件一致。受限文档的读者预览/引用/下载拒绝响应 404；撤权和撤回后，旧回答段被 `MASKED`，没有正文或引用。
- **工作台检索**：选中助手后检索「费用分摊」，命中 `FIN-TR-017` §3.3 并打开文档预览；`绒冠蜥保育周期` 返回明确的空结果说明，不展示无关命中。
- **设置与统计**：从 UI 建账号、授予空间权限、管理模板和助手、启停合成模型配置、恢复全局设置；普通用户个人统计和管理员全量、单用户、趋势、排行与空间用量都读回核对。窄屏宽度为 390 px，页面无横向溢出。

详见[测试矩阵与运行方法](ai-qa-e2e-plan.md)、[前端入口说明](../frontend/README.md)。

## 真实模型验收

隔离栈通过本机 Magpie 网关（`http://127.0.0.1:3425/v1`，OpenAI 兼容协议，模型 `auto/deepseek-v4.1-flash`）接入真实模型：`E2E_REAL_MODEL=1`、`RELEVANCE_GATE=model`，凭据只经环境变量 `AIQA_MODEL_CREDENTIALS_MAGPIE` 透传，不写入代码或数据库。流程新增 `AD03-REAL`：通过接口建立模型配置（`openai_compatible`、该网关注册为默认模型），随后所有问答走真实模型。

- **`QA09` 通过模型判定拒答**，不是靠规则放行。后端日志为该问题的判定结果：`资料仅涉及住宿限额、报销时限及驻点津贴，未提及早餐报销额度`。`QA10`、`QA20` 在词法门控即返回无依据（候选为空），未调用模型。
- `QA07`（待核实口径）返回 `UNCERTAIN`：判定提示明确「资料标注待核实仍属有依据，应说明状态而非拒答」，证据行同时带 `UNCERTAIN` 标签。
- 20 题答案由模型生成自然语言，不再是逐字摘录；引用仍逐条回读核对版本与位置。
- 判分侧修正两处字面误判：判分前去掉 Markdown 强调标记（`**`、`` ` ``、`__`），`QA12` 的「到达目的地后」与「24 小时内」拆成两个事实分别核对。这两项只改测试代码，不放宽事实要求。

## 向量召回（本机小模型）

嵌入用本机 `llama.cpp` 起的小模型 `qwen3-embed`（Q8_0，1024 维），OpenAI 兼容 `/v1/embeddings`，不需要外部密钥：

```sh
llama-server -m .cache/models/qwen3-embed-q8_0.gguf \
  --embedding --pooling last -c 1024 -b 512 --host 127.0.0.1 --port 3437
```

- 解析与重建索引时按批写入 `document_chunk.embedding`（`real[]`，迁移 V14）。本轮断言 `EMB-01`：45 个文本块全部有向量，维度 1024；未启用嵌入时 `EMB-OFF` 断言向量数保持 0。
- 检索时词法候选扩到 60 条，再取同范围内余弦最接近的 60 条向量候选，按 0.45×词法 + 0.55×向量混合排序，纯向量候选需达到本次最高相似度的 75% 才可进入，最多 20 条进模型。
- 嵌入服务不可用时向量为空，检索自动回退词法，导入与问答都不失败。
- 本轮结果：81/81 流程、20/20 质量题；Recall@20 100%、Hit@5 17/17；延迟均值 11.39 s、p95 32.07 s（向量计算本身约 150 ms，主要耗时在模型生成）。

## 语义相关性门控

词法规则判断不了"被问的对象在资料里根本不存在"。为此新增模型判定：回答前把问题与前 8 条候选证据发到同一网关，只要求一行 JSON 判定；不足以支撑时按 `NO_EVIDENCE` 返回且不写引用，判定失败按失败开放继续回答，判定自身的 Tokens 单独记一条用量。

本轮隔离运行以 `RELEVANCE_GATE=fake` 只验证接线（判定一律通过），因此基准分数不受判定器影响，仍是 79/79 与 19/20。**真实模型尚未配置**：缺少网关地址、模型 ID 与凭据引用，`QA09` 能否转成 `NO_EVIDENCE` 以及其余 19 题是否被误拒，都必须在配置后重跑本报告的全流程才能确认。

## 遗留项与边界

- 本地替身基线（`61e469e1`）仍把 `QA09` 记为失败：替身不做语义判断，拒答依赖判定器，而基线刻意以 `RELEVANCE_GATE=fake` 只验证接线。真实模型下该题已通过。
- 判定器失败时按失败开放继续回答，因此网关不可用时表现回到「有无依据由词法门控决定」；这一分支尚未在真实网关故障下演练。
- 向量检索目前是「内存里算余弦 + 2000 块扫描上限」，适合当前语料规模；块数上千后应换成 pgvector（本机 PostgreSQL 未安装该扩展）或数据库侧近邻索引。
- XLSX 表头上下文改变了新导入文档的证据文本。已上线环境需对相关空间执行 `POST /spaces/{spaceId}/reindex` 才会生效；历史引用使用已冻结的证据片段，不会被改写。
- 没有使用真实业务原件；本轮真实模型只看到合成题卡。并发审核、解析失败后重试、跨时区/月末边界、Safari/Firefox、辅助技术和压力测试未覆盖。[测试计划与下一步](ai-qa-e2e-plan.md#运行方法)
