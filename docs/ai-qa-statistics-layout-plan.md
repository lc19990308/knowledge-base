# 问答统计页信息架构重排方案（2026-11-26）

## 现状与问题

1440×900 实测：页面总高 **1920px（约 2.1 屏）**，需要滚动，且明细默认折叠、展开后还需再滚。

| 区块             | 当前高度 | 问题                                                                            |
| ---------------- | -------- | ------------------------------------------------------------------------------- |
| 页头筛选         | 45       | 正常                                                                            |
| KPI 4 卡         | 118      | 大卡铺满一行，信息密度低                                                        |
| 提问与失败趋势   | 328      | 图 220 + 图例，留白多                                                           |
| 排行 + 空间指标  | 442      | 两张长表并排，行少时大片空白，行多时无限拉长                                    |
| 提问明细（折叠） | 744      | 需展开；内含时间分布柱状图 + 状态环形图 + 表格，与上方趋势图重复；表格只露 5 行 |

核心问题不是"缺图表"，而是**同一件事画了两遍、区块各占一张大卡**：趋势图与明细时间分布图都在讲"时间维度的提问量"；状态环形图与 KPI 失败率重复。

## 设计目标

1. 1440×900 一屏放完，页面本身不滚动（明细在表内滚动）。
2. 明细不折叠，进页即可见。
3. 图表只保留一张主图，状态用轻量堆叠条表达，避免"图表铺满"。
4. 所有信息保留，不删业务字段，只压缩表达。

## 推荐方案 A：单页紧凑仪表盘（四段式）

```
┌ 问答统计 ────────────────────────────────────────────── 自然周 | 2026/11/26 | 用户 ▾ ┐
├ 会话 19 │ 提问 28 │ 失败 3（10.7%） │ Tokens 40,473（未上报 0） ────────────── 72px ┤
├───────────────────────────────────────────────┬──────────────────────────────────┤
│ 提问与失败趋势（折线 + 虚线，高 200）          │ 状态构成                          │
│                                               │ 已回答 ███████████ 120            │
│                                               │ 生成中 ███ 40                     │
│                                               │ 处理失败 ███ 40                   │  230px
├───────────────────────────────────────────────┴──────────────────────────────────┤
│ 用户 Top 5（姓名 · 提问 · 失败 · Tokens）  │  空间 Top 5（空间 · 引用 · 覆盖提问）  │  180px
│ 小计：3 位用户 / 2 个空间被引用 ────────────────────────────────────────────────── │
├──────────────────────────────────────────────────────────────────────────────────┤
│ 提问明细 · 最近 200 条 / 共 28 条（北京时间）                    [滚动查看全部]      │
│ 时间 │ 用户 │ 提问 │ 状态 │ Tokens │  ← sticky 表头                               │
│ … 表内滚动 …                                                                    │  240px
└──────────────────────────────────────────────────────────────────────────────────┘
```

### 各段做法

1. **KPI 指标带**（118 → 72）
   - 取消 4 张独立大卡，改一行条带：`label` 小字 + 数值 + 副文本。
   - 副文本承载现有明细：失败率跟"失败请求数"，未上报次数跟"Tokens"。

2. **主图 + 状态条**（328 + 饼图 → 230）
   - 只保留「提问与失败趋势」一张折线图，高 200，失败用虚线（现状）。
   - 状态构成从环形图改为**堆叠条 + 图例数字**（已回答/生成中/处理失败），色值沿用 `--color-success` / `--color-warning` / `--color-danger`；宽度占 1/3，高度 200。
   - 删除明细区的时间分布柱状图（与趋势图同义）。

3. **排行 + 空间合并成"结构"卡**（442 → 180）
   - 两列并排，各显示 **Top 5**，行高 32；超出部分显示「另有 N 位 / N 个」。
   - 用户列：姓名、提问数、失败数、Tokens；空间列：空间名、被引用次数、覆盖提问。
   - 底部一行汇总替代原来的"合计"行。

4. **明细平铺**（744 → 240）
   - 去掉 `<details>`，直接展示；删除明细区的两张图与口径说明（趋势/状态已在上方，口径统一为"最近 200 条明细"）。
   - 表格固定高 240（约 6 行），表头 sticky，表内滚动查看 200 条。
   - 顶部工具条显示「最近 200 条 / 共 N 条」；如需可加状态筛选（暂不做，避免范围扩大）。

### 高度预算

| 段          | 高                      |
| ----------- | ----------------------- |
| 页头        | 45                      |
| KPI 带      | 72                      |
| 主图 + 状态 | 230                     |
| 结构卡      | 180                     |
| 明细        | 240                     |
| 间隙 4×16   | 64                      |
| 合计        | **831**（内容区约 852） |

### 响应式

- ≤1100px：主图与状态、结构两列各收为单列；明细表横向滚动。
- ≤640px：KPI 2×2；其余单列，页面可滚动（移动端不强行一屏）。

## 备选方案

| 方案               | 做法                                               | 优点               | 缺点                                       |
| ------------------ | -------------------------------------------------- | ------------------ | ------------------------------------------ |
| B 双栏工作台       | 左 60% 概览（KPI+趋势+状态），右 40% 明细常驻      | 明细与趋势同屏对照 | 右栏窄，提问文本截断；结构卡需另找位置     |
| C 概览/明细 Tab    | 顶部两个 Tab，概览页放 KPI+趋势+结构，明细页放表格 | 每页最清爽         | 需切换，不满足"一屏看全"；对账时看不到汇总 |
| D 保持现状仅去折叠 | 只把明细展开、图压缩                               | 改动最小           | 仍是 2 屏，不符合诉求                      |

推荐 **A**：在不丢字段的前提下，用"压缩表达 + 合并同义图"换一屏。

## 实施步骤

1. `StatisticsView.vue` 模板重排：KPI 条 → 主图 + 状态条 → 结构卡 → 明文明细。
2. 删除 `detailTimeOption`、`detailStatusOption` 及相关样式；新增状态堆叠条的计算（按状态计数 + 百分比宽度）与 Top 5 截断。
3. 样式：新增本页 scoped 的紧凑间距（`--space-2/3`）与明细表 `max-height: 240px; overflow: auto`，表头 `position: sticky; top: 0`；沿用现有 token，不新增全局变量。
4. 响应式沿用现有 640/1100 断点。

## 验收标准

- 1440×900：`document.documentElement.scrollHeight ≤ 900`，页面无纵向滚动条；明细可见且表内可滚动到第 200 条。
- 200 条明细下，趋势、状态、Top 5、汇总数字与接口数据一致。
- 深色主题、390px 窄屏无横向溢出（保持现有修复不回退）。
- `npm run lint`、`npm run typecheck` 通过；浏览器截图留证。

## 确认与实施结果

已确认采用方案 A，排行/空间各显示 Top 5 + "另有 N 位"，明细固定高度表内滚动。

实际实施后 1440×900 的页面总高为 **900px（等于视口，无整页滚动）**，明细表 `max-height: 200px`（约 6 行）内部滚动。实施记录、压缩后的真实高度与验证结果见[变更记录](./ai-qa-change-2026-11-26-statistics-layout.md)。
