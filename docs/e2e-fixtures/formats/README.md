# 差旅文件格式 E2E 夹具 v1.0

沿用上级样本中的虚构企业「北岸设备服务」。文号 `FIN-FMT-101` 至 `FIN-FMT-107`、金额、日期、业务流程和凭证记录均为本包原创的合成数据。每份材料均标有「合成测试资料｜仅用于 E2E」。预算台账采用本包独立的模拟口径，建议在专用测试空间单独使用。

仅从 `upload/` 选择原件。题卡和 [SHA-256 校验清单](SHA256SUMS) 留在测试侧。可将七份原件一起提交，按文件核对结果。预期五份有正文的原件进入 `READY`，图片 PDF 进入 `NO_TEXT`，扩展名与内容不符的文件在接入时被拒绝。以下状态是基于当前实现的 E2E 预期。

## 生成来源与本地验证

正文 PDF 由 macOS Core Graphics / Core Text 直接写入嵌入文字。扫描样本先栅格化自制交接单，再将整页位图写入 PDF。DOCX、XLSX、PPTX 分别用工作区提供的 `python-docx` 1.2.0、`openpyxl` 3.1.5、`python-pptx` 1.0.2 生成。TXT 和错误扩展名样本由 Python 写入 UTF-8。业务内容无外部来源。

在当前目录运行 `shasum -a 256 -c SHA256SUMS`。本地验证使用 `file` 检查格式，并离线调用项目的 `FileScanner`、`TextExtractor` 检查原件。五份正文样本的块数依表序为 7、8、11、6、4，且上表正文锚点均命中预期位置。PDFBox 解析并渲染了扫描页，确认一张图片、无字体资源和文字对象，提取结果为 0 块。错误扩展名样本重现 `REJECTED` / `SUSPICIOUS_FILE`，PDFBox 也拒绝打开。验证未运行上传、索引、发布或重试 E2E 流程。
