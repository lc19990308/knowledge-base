# AI 智能问答平台全站 E2E 测试计划

## 验收目标

从浏览器登录开始，连接实际的 Spring Boot、PostgreSQL、本地对象存储与后台任务。沿着同一份文件的 `documentVersionId` 核对导入、草稿、冻结快照、发布、检索、回答引用及原件下载。页面操作、HTTP 响应和服务端读回三处都要一致。按角色分别验证常规入口、拒绝访问、撤权后的历史内容和统计。

## 运行方法

运行需要兼容 Vite 7 的 Node.js、Java 17+、Maven、PostgreSQL 的 `initdb` / `postgres` / `psql`，以及系统已安装的 Chrome。Playwright 1.55.1 已锁定为前端开发依赖。执行前准备前端锁定依赖和 Maven 缓存；Runner 用 `mvn -o` 构建隔离的后端源码副本。

```sh
cd frontend
npm ci
npm run test:e2e
```

若 Playwright 已可由前端 Node 模块解析，直接运行 `npm run test:e2e`。Chrome 默认使用 `chrome` 通道。已用 Playwright 安装 Chromium 时可设置 `E2E_BROWSER_CHANNEL=chromium`。依赖准备只在首次运行或缓存清空后需要。测试使用独立本地环回端口和 Cookie 会话。Runner 复制后端源码、生成隔离数据库及对象目录、构建 Vite 正式产物并启用专用的 `/api` 代理。执行结束收回本轮服务和数据目录，证据保留在终端显示的报告目录。

浏览器关键写请求从页面发出，读回与权限边界验证使用同角色 Cookie 和真实 CSRF。每轮用新数据库和新运行 ID。解析、审核发布、回答等候终态的接口轮询有截止时间。测试失败保留错误码、请求或资源 ID、错误截图。出现环境问题先看 `maven.log`、`postgres.log` 和 `backend.log`。对未返回结果的写入先按 ID 对账，再决定是否重放。

## 已知限制与验收口径

`QA09`（差旅早餐额度）曾长期未通过。**2026-11-25 用真实模型验收后已通过**：模型判定资料未涉及早餐报销额度，回答按 `NO_EVIDENCE` 返回且无引用（运行 `3d10e9a8`）。

本地替身（`FakeAnswerModel`）不做语义判断，所谓"拒答"只能靠判定器；因此替身基线刻意设 `RELEVANCE_GATE=fake`，该题在基线里仍记为失败。两条结论并不矛盾：**替身只验证接线与检索质量，语义拒答由真实模型验收**。

## 语义相关性判定（门控）

配置了默认模型后，回答前会先做一次模型判定：把问题与前 8 条候选证据（每条截断 600 字）发给同一网关，要求只回一行 JSON `{"sufficient":true|false,"reason":"…"}`。判定为不足以支撑时，回答按 `NO_EVIDENCE` 返回且不写引用；判定调用失败按**失败开放**继续回答，避免判定服务抖动连带拦掉正常问答。判定消耗的 Tokens 单独记一条用量，统计里不丢。

| 开关                                       | 值              | 行为                                          |
| ------------------------------------------ | --------------- | --------------------------------------------- |
| `RELEVANCE_GATE` / `aiqa.answer.relevance` | `model`（默认） | 有默认模型时调用网关；未配置模型时旁路        |
| 同上                                       | `fake`          | 一律通过，隔离 E2E 只验证接线，不替基准题判赢 |
| 同上                                       | `off`           | 关闭判定                                      |

超时 `RELEVANCE_TIMEOUT`（默认 `PT20S`）。真实模型验收已完成（`3d10e9a8`）：`QA09`、`QA10`、`QA20` 均返回 `NO_EVIDENCE` 且无引用，其余 17 题不被误拒。

真实模型运行方式（凭据只走环境变量）：

```sh
cd frontend
E2E_REAL_MODEL=1 RELEVANCE_GATE=model \
AIQA_MODEL_CREDENTIALS_MAGPIE=local \
E2E_MODEL_BASE_URL=http://127.0.0.1:3425/v1 \
E2E_MODEL_NAME=auto/deepseek-v4.1-flash \
npm run test:e2e
```

`E2E_REAL_MODEL=1` 会追加 `AD03-REAL`：经接口建模型配置并设为默认；随后所有问答与判定都走该网关。不设该变量时行为与之前完全一致（本地替身）。

向量召回已接入本机嵌入模型 `qwen3-embed`（llama.cpp，1024 维，`/v1/embeddings`）：`E2E_EMBEDDING=1` 时索引写入 `document_chunk.embedding`，检索按 0.45 词法 + 0.55 向量混合排序，纯向量候选需达到最高相似度的 75%。嵌入服务不可用时回退词法。验收运行 `c02c96a5`：81/81 流程、20/20 质量题。

## 答案质量与发布门槛

- 每题分别检查接口终态、答案类型、必备事实/单位、禁项、引用 ID 归属、来源文件版本及页码/章节/行号。逐条记录题目、预期、实际答案、引用和耗时。正则只核对字面线索，表格和跨政策关系需要读原件复核。
- 在隔离库读取模型实际收到的有序候选，记录证据召回率@20 和前 5 命中率。有答案题参与分母。无相关来源的题核对明确的 `NO_EVIDENCE`、零引用和无越权内容。无法采集排名时指标留空。[指标定义](ai-qa-retrieval-evaluation.md)
- 按当前授权运行本地 `FakeAnswerModel`。它返回前三条候选摘录和估算用量，可复现检索、引用、页面与权限的行为。真实模型生成质量、网关联通和真实 Tokens 的验收另行使用业务方获准提供的脱敏原件、问题和固定模型配置。
- `cases.jsonl` 记录过程断言，`quality.json` 记录二十题评分，`summary.json` 汇总两组结果，`spaces.json` 保留批次/快照/原件 ID。`browser-events.json` 只记录路径、状态及请求 ID，失败截图遮住密码输入。功能或质量有 `FAIL` / `BLOCKED` 时命令退出 `1`。重跑遇到同一功能偏差，保留这个失败作为回归门槛。

本轮深入验证 Chromium 桌面端、390 px 工作台、核心操作路径和列明的数据边界。解析失败后的恢复、索引排队故障、并发审核/写入、跨时区或月末边界、Safari/Firefox、性能负载、屏幕阅读器、真实企业文档和真实模型属于后续验收项。落地环境、实际结果和缺陷见[全站 E2E 测试报告](ai-qa-e2e-run-2026-11-25.md)。
