# AI 智能问答平台｜产品需求文档（PRD v0.5）

- 版本日期：2026-11-20（2026-11-22 修订需求，2026-11-23 核对实现）
- 状态：首期需求评审稿。已确认的业务规则与建议口径分别标注；本文不代表系统已实现或通过验收。
- 配套：[首期技术方案](./ai-qa-technical-design.md)

## 1. 目标与范围

首期面向登录用户，提供基于已审核政策资料的搜索和问答。用户应能核对答案出处；管理员应能控制哪些空间可以被访问，并在撤回后阻止旧引用和后续追问继续暴露内容。

业务主线：**创建知识空间 → 导入并处理文档 → 提交审核（驳回后修改重提）→ 发布 → 授权用户搜索和问答 → 变更重审或撤回**。问答产生的用量按用户统计，文档类指标按空间统计。

首期包含工作台、知识库、AI 助手与助手配置、回答模板、发布管理、问答统计和系统权限/全局模型配置。不支持匿名访问和扫描件 OCR。文档级引用仍是验收下限，当前实现可在有来源信息时额外展示命中文本和页码、标题或表格行等位置提示。收藏等截图中可见但尚未明确规则的能力不作为核心链路的验收前置条件。

## 2. 角色与权限

管理员与普通用户均使用本地账号密码登录。企业单点登录已移出交付范围。

| 角色 | 可以做什么 |
| --- | --- |
| 普通用户 | 登录后搜索、查看和使用有权限且已发布的知识空间；通过助手提问并核对文档引用。 |
| 获授维护权限的提交用户 | 在授权范围内维护空间、导入文档、提交发布审核；被驳回后修改并重新提交。维护权限不等于发布权限。 |
| 系统管理员 | 管理权限和全局设置，开放助手可绑定的空间，审核或驳回发布申请，并执行发布撤回。 |

助手绑定多个空间不扩大用户权限。作为普通用户使用的搜索、问答、引用、文档预览与下载都受同一访问规则约束。当前登录用户不能用历史会话或旧链接绕过撤回。

## 3. 页面与业务规则

### 3.1 工作台与空间搜索（R01）

工作台提供知识空间入口、创建与导入操作（按权限显示）、最近会话和助手入口。文档数、可检索文档数按空间统计，并标明对应空间与数据范围。搜索对象为所选空间内的文档，支持文档名称及正文检索，不把空间名称当作文档正文结果。区分未处理完成、没有匹配结果和空间不可访问，避免把三者都显示成「0 条」。

### 3.2 导入与版本管理（R02）

- 支持常用文档格式；建议首期以 PDF、Word、Excel、PowerPoint、TXT、Markdown 建立验收样本，具体扩展名及大小限制以导入支持矩阵为准。
- 同名文件跳过，不覆盖原文件；上传新版前必须改名。建议同名判定限定在同一空间。已入库的新旧版本均可检索，不因新版导入自动下架；空间撤回时，全部版本不再对原授权用户开放。
- 首期不做 OCR。有可提取文字的文件按已有文字处理；纯扫描件须提示「无法提取正文」，不计入可检索文档数。
- 导入须反馈处理结果：可检索、同名已跳过、无可提取正文或处理失败。批量导入逐文件展示结果；技术性失败可重试，不必重新导入已成功文件。

### 3.3 助手与政策回答（R03）

- 一个助手可绑定多个管理员开放的空间，实际回答只使用当前用户有权访问且已发布的空间。指定空间没有检索到资料时，不自动扩展到其他未授权空间。
- 助手回答模板优先于全局模板。提问默认使用全局配置的模型，用户可为单次提问选择可用模型。模板不得覆盖权限、引用和政策有效性规则。
- 正常回答给出所用文档的引用，打开引用能定位到具体文档，不要求定位到页码或条款。不能从授权文档得出结论时，明确说明无依据，不编造。
- 新旧版本均可检索，但可检索不等于有效。政策已失效时明确提示，不将其作为现行依据；有效性无法核实时标注「有效性待核实」。政策冲突时逐项标出差异，并分别给出对应文档，不以单一结论掩盖冲突。

### 3.4 提交、审核与撤回（R04）

| 场景 | 规则 |
| --- | --- |
| 首次发布 | 发布对象是知识空间。提交后由系统管理员审核，审核通过后，登录且获权用户才可访问。 |
| 驳回重提 | 提交用户查看驳回原因，完成修改后重新提交；驳回版本不得对用户开放。 |
| 已发布空间变更 | 变更须重新审核才能生效。在通过前，未审变更不得出现在用户搜索、问答和引用中。建议沿用上一个已审版本，直到新版本生效。 |
| 撤回发布 | 原已授权用户也不能再查看。新提问、搜索、文档详情以及旧链接均不得返回撤回空间的内容。 |
| 历史与继续追问 | 保留历史会话，但移除撤回来源的引用，并屏蔽依赖撤回内容的整段回答（即使该段同时引用了仍可用的文档）。未受影响的段落保留；继续追问不得复用已屏蔽内容。 |

### 3.5 问答统计（R05）

会话数、提问次数、失败请求数和 Tokens 均按发起操作的用户归属；一次提问用到多个空间也只计一次。Tokens 以实际用户用量为准。统计统一使用北京时间（`Asia/Shanghai`），支持自然日、自然周、自然月，不使用滚动窗口。

建议的明细口径：自然周按周一至周日；一次已受理的提问计一次，最终失败同时计入失败请求；网络重复提交和服务内部重试不新增提问数，用户主动重新提问视为新请求。模型未上报用量时标记「未上报」，不记为零用量。仅文档类指标按空间统计。

## 4. 首期验收用例

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| AC01 | 并发导入同名文件；改名后导入新版；再导入纯扫描件 | 同名只接受一份且原文件未覆盖；已发布的新旧版本均能按正文找到；纯扫描件提示无正文且不计入可检索数。 |
| AC02 | 制造一次解析失败后重试，再搜索已修复文档 | 可见失败原因；重试后文档可检索，没有重复记录或索引。 |
| AC03 | 助手绑定 A、B，用户仅获 A 权限；分别搜索、提问和打开引用 | 不返回 B 的名称、摘要、正文或引用；能正常查阅 A 的文档；助手模板覆盖全局模板。 |
| AC04 | 用正常、无依据、失效、有效性不明、冲突样例分别提问 | 有依据时可核对文档；其他场景给出对应提示；冲突逐项列出差异和各自来源。 |
| AC05 | 驳回首次申请，提交者修改重提；发布后再提交文档或政策状态变更 | 驳回原因可见；两次通过后才分别开放对应内容；重审期间未审变更不可见。 |
| AC06 | 撤回一个带历史引用的空间，用原获权账号访问、打开旧链接并继续追问 | 搜索与新回答不再使用撤回内容；旧链接打不开；历史只屏蔽受影响段落并移除相关引用，追问不复用。 |
| AC07 | 用跨空间提问、重复请求、失败和北京时间跨周期的固定记录对账 | 用户维度只累计一次逻辑提问；会话、失败及 Tokens 可与原始记录核对；自然日、周、月边界正确。 |

验收建议使用一组有业务标准答案的政策文件，至少覆盖新旧版、冲突、失效、扫描件和越权样例。自动化覆盖和待验收项见[实施状态](./ai-qa-status.md)。

## 5. 当前实现对照（2026-11-23）

- **导入（R02）**：支持 `.pdf`、`.docx`、`.xlsx`、`.pptx`、`.txt`、`.md`。单批最多 10 个文件，单文件 100 MiB，整批默认最多 200 MiB。部署可以收紧整批限制。
- **助手（R03）**：首次提问自动建会话，支持归档、恢复和删除。归档会话保留历史，恢复后可继续提问。页面保留连续对话记录，每次模型调用使用当前问题及本次检索证据。
- **引用与冲突（AC03、AC04）**：新引用可展示命中的原文片段、可用的来源位置、文档版本和有效性。当前冲突标记基于同名有效文档存在多个版本，针对不同文件的政策冲突及差异逐项列举仍需业务样本验收。
- **Tokens（R05、AC07）**：以真实网关上报为准。默认开发模型返回估算值，未上报用量的调用保留缺失状态。
